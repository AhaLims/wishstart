# 许愿星计划 - 桌面端架构设计

> 状态：已确认基线，开始实现
> 关联文档：`docs/技术设计文档.md`（网页版架构，仍有效）、`docs/核心功能--思考实现系统.md`（需求来源）

---

## 1. 目标

在现有「网页端 + Docker 容器」基础上，新增 **Windows 桌面端（.exe）**：

- 桌面端为主要使用端：集成工作计时（正计时/倒计时），自动结算「时间型任务」。
- 网页端保留：维持「手动完成任务」方式，**不引入计时功能**，仅偶尔记录使用。
- 双端数据可互通：通过统一 JSON 快照导入/导出（覆盖式 + 自动备份）。
- 数据全部本地存储，单用户、KB 级数据量，无需外部数据库。

## 2. 总体架构

```
                        ┌──────────────────────────────────────────────┐
                        │              桌面端 (Windows .exe)            │
                        │  ┌────────────────────────────────────────┐  │
                        │  │  Electron 主进程 (Node.js)             │  │
                        │  │  ├─ Express 服务 (与网页端同一套路由)   │  │
                        │  │  ├─ JsonFileStore（本地 JSON 数据文件） │  │
                        │  │  └─ 静态托管 frontend/dist             │  │
                        │  └────────────────────────────────────────┘  │
                        │  Electron 渲染进程：Vue 3 前端（与网页端复用）│
                        └──────────────────────────────────────────────┘

网页端（Docker Compose，不变）：
  Vue 3 + Express + Redis（或 Memory 兜底）
```

- 两端共用**同一套 Express 路由代码**（`backend/src/routes/*`），通过存储抽象层切换数据源。
- 桌面端 = 同一套后端 + 本地 JSON 存储 + Electron 窗口壳。
- 计时/结算等新功能只在桌面端可用；网页端不渲染计时 UI。

## 3. 技术选型

### 3.1 桌面壳：Electron（预留 Tauri 切换路径）

- 复用现有 Node/Express 后端，开发与打包最省事。
- 提供原生桌面通知（倒计时结束提醒）、单实例锁、开机自启、托盘等能力。
- **切换到 Tauri 的降级路径**（仅当内存吃紧时再考虑）：
  - 前端 Vue 完全复用；
  - 存储格式（JSON 快照）语言无关，Rust 端用 serde 直接解析同一数据文件；
  - 业务规则沉淀在本文档 + 契约测试集，重写后端后跑同一套测试验证。

### 3.2 本地存储：JSON 文件（不用 SQLite）

| 考量 | 结论 |
|------|------|
| 数据量 | 单用户，KB~几十 KB 级，JSON 完全够用 |
| 同步格式统一 | 双端同步快照本就是 JSON（`wishstar:*` 键值结构），本地文件即快照格式，导入/导出零转换 |
| 零原生依赖 | 避免 better-sqlite3 在 Electron 打包时的 native 模块重编译（electron-rebuild）与跨平台构建摩擦 |
| 可靠性 | 原子写（临时文件 + rename）+ 每次保存保留 `.bak` + 导入前自动备份，对本场景足够 |

- 数据文件位置（桌面端）：`app.getPath('userData')/wishstar-data.json`
- 数据文件结构：见第 4 节。
- 存储接口与 Redis 完全兼容，未来若数据量增大，可新增 SqliteStore 实现替换，路由零改动。

### 3.3 存储抽象层

路由代码只依赖一套异步方法（与 Redis 命令一一对应），`req.redis` 实际是 store 实例：

```
hget / hset(单字段) / hset(批量对象) / hgetall / hincrby
sadd / smembers / srem
zadd / zrange / zrevrange / zrem
lpush / lrange
del
exportSnapshot / importSnapshot   （同步快照专用，新增）
flush                             （JSON 存储落盘专用）
```

实现：
- `RedisStore`：现有 ioredis 逻辑（网页端默认）
- `JsonFileStore`：新实现（桌面端默认）
- `MemoryStore`：现有兜底（开发环境）

选择方式：环境变量 `STORAGE=redis|json|memory`。

## 4. JSON 数据文件格式

```json
{
  "version": 1,
  "data": {
    "wishstar:user:default_user": {
      "t": "hash",
      "f": { "id": "default_user", "total_stars": "165", "current_stars": "4" }
    },
    "wishstar:tasks:index:default_user": {
      "t": "set",
      "m": ["<taskId>", "..."]
    },
    "wishstar:records:default_user:2026-08-14": {
      "t": "zset",
      "z": [[1786072901016, "{...recordJson...}"]]
    },
    "wishstar:draws:default_user": {
      "t": "list",
      "l": ["{...drawJson...}", "..."]
    }
  }
}
```

- `t`：类型 `hash|set|zset|list`；`f/m/z/l`：对应数据。
- 所有值保持字符串，与 Redis 行为一致（数字字段也是字符串，业务代码自行 `parseInt`）。
- zset 按 score 升序存储；`zrange` 升序返回，`zrevrange` 降序返回（与 Redis 语义一致）。
- 该文件即「导出快照」，可直接用于双端同步与容器数据迁移。

## 5. 新增功能设计

### 5.1 工作时间会话（work_sessions）

数据：hash `wishstar:work_session:{sessionId}` + 当日索引 zset `wishstar:work_sessions:{userId}:{date}`。

字段：
| 字段 | 说明 |
|------|------|
| id | 会话 ID |
| user_id | 用户 ID |
| date | 归属日期（北京时间，按开始时间） |
| mode | `count_up`（正计时）或 `countdown`（倒计时） |
| planned_minutes | 倒计时的计划分钟数（正计时为 0） |
| started_at | 开始时间戳 |
| ended_at | 结束时间戳（未结束为空） |
| actual_seconds | 实际工作秒数 |
| completed | 倒计时是否完整走完（0/1） |
| status | `running` / `completed` / `stopped` |

接口（`backend/src/routes/work.js`）：
- `POST /api/v1/work/sessions`：开始会话
- `POST /api/v1/work/sessions/:id/end`：结束会话，触发时间型任务结算，返回汇总
- `GET /api/v1/work/sessions/today`：今日会话列表 + 总秒数 + 各时间型任务进度
- `GET /api/v1/work/status`：当前运行中的会话（App 重启后恢复）
- `GET /api/v1/work/today`：今日汇总（总秒数、次数）

规则（已确认）：
- 正计时：从 0 累计，`actual_seconds = ended_at - started_at`。
- 倒计时：完整走完按 `planned_minutes * 60` 计入；中途停止按实际已计时的秒数计入。
- 跨零点会话归属「开始当天」。
- 会话运行中关闭 App：数据已持久化，重启后通过 `/work/status` 恢复展示「未结束会话」。

### 5.2 时间型任务与自动结算

任务增加字段：`task_type`（`general`/`time`）、`minutes_per_complete`（工作多少分钟自动完成一次）。

结算数据：hash `wishstar:task_credits:{userId}:{date}`，字段 `{taskId: 已结算次数}`。

规则（已确认）：
- 当日总工时 = 当日所有会话 `actual_seconds` 之和（跨天按开始日期归属）。
- 每个 active 时间型任务独立折算：`应结算次数 = floor(当日总分钟 / minutes_per_complete)`，差额补齐。
- 结算复用「手动完成任务」的同一套奖励逻辑（`backend/src/services/completions.js`）：
  - 周末翻倍、今日星星累计、骰子次数累计、任务完成次数、每日记录、流水，与手动完成完全一致。
- 时间型任务不设完成次数上限。
- 每日从 0 开始，`floor` 后的余数当天作废、不跨天滚存。
- 触发时机：**工作期间每满一个周期即时入账**（渲染层检测到阈值跨过 → 调结算 → 页面小字提示「已获得 1 颗星 ⭐」，不弹窗）；**结束工作时弹确认框汇总**（「本次 60min，自动完成 2 次 25min 任务，获得 2 颗星」）。过程中已入账，确认框不重复入账。
- 结算时**运行中会话的实时时长也计入当日工时**（`POST /api/v1/work/settle` 会把运行中会话的 elapsed 作为额外秒数传入），保证工作期间的阈值结算真实入账。

### 5.3 桌面通知

倒计时结束时由渲染层检测（`setInterval` + 时间戳差值），通过 Electron 渲染进程 HTML5 `Notification` 弹通知「倒计时结束」。仅通知，不做声音。

## 6. 双端同步（快照导入/导出）

- 后端接口：`GET /api/v1/sync/export`、`POST /api/v1/sync/import`（两端同一套代码，Redis/JSON store 均实现）。
- 桌面端：设置页提供「导出快照」「导入快照」（文件选择器）。
- 网页端：同步入口（下载/上传 JSON 文件）。
- 策略（已确认）：**覆盖式写入 + 导入前自动备份**。
  - JSON store：导入前把当前文件备份为 `wishstar-data.pre-import-{ts}.json`。
  - Redis store：导入前先把当前全量导出为备份文件（暂由前端下载兜底，Web 端实现时细化）。
- 使用模式：一段时间只用一端 → 用完后导出 → 另一端导入，直觉无歧义。

## 7. 数据迁移（容器 → 桌面端）

1. 在跑容器的机器（WSL）执行 `node scripts/export-redis.js`，连接 `localhost:6379`：
   - `SCAN MATCH wishstar:*` 遍历全部键，按类型导出为 `wishstar-export.json`；
   - 跳过垃圾键（如 `wishstar:wish:ERR unknown command 'UUID'`）；
   - 打印摘要（total_stars / 任务数 / 愿望数 / 记录天数），供导入后校验。
2. 桌面端设置页「导入快照」选择该 JSON → 覆盖式导入（自动备份）。
3. 校验：对比导入前后的 `total_stars`、`current_stars`、任务/愿望数量。
4. 校验通过前**不停容器**；导出 JSON 本身就是完整备份，保留一份。

## 8. 契约测试计划（为未来 Tauri 切换铺路）

- 以真实容器数据为 golden 数据：固定一份测试用快照 + 一组操作序列（创建任务/完成/骰子/抽卡/工作结算…）。
- 两端（Node/未来 Rust）跑同一组输入，对比输出 JSON（奖励、计数、记录、流水）。
- 目的：换后端语言时验证规则一致性，不靠肉眼回归。
- 落地位置：`scripts/contract/`（后续迭代补充）。

## 9. 桌面端目录结构与打包

```
wishstart/
├── package.json            # 根包：electron / electron-builder 脚本
├── electron/
│   └── main.js             # Electron 主进程：单实例锁、启动后端、创建窗口
├── backend/                # 共用后端（Express + 存储抽象）
├── frontend/               # 共用前端（Vue 3），构建产物 frontend/dist
├── scripts/
│   └── export-redis.js     # 容器数据导出脚本
└── docs/
```

- 打包：`electron-builder`，目标 `nsis`（安装版）+ `portable`（绿色版）。
- 构建环境：建议在 Windows 上执行 `npm run dist:win`（Linux 交叉打包需要 wine，体验差）。
- 图标：后续提供 `.ico` 后配置。

## 10. 已确认业务规则清单（基线）

1. 倒计时中途停止：已计时分钟计入当日总工时并参与结算。
2. 跨零点会话：归属开始当天。
3. 自动结算：周末翻倍、骰子次数累计与手动完成完全一致。
4. 时间型任务：仅使用 1 个（25min）；实现支持多个、各自独立折算；不限制完成上限。
5. 每日工时从 0 累计，余数不跨天滚存。
6. 结算触发：过程中每满 25min 即时入账 + 小字提示；结束工作确认框汇总（不重复入账）。
7. 倒计时结束：仅桌面通知，无声音。
8. 网页端：不显示今日工时；时间型任务卡片显示但隐藏「完成」按钮（防双重计数）。
9. 双端同步：覆盖式导入 + 自动备份。
10. 时间型任务奖励支持星星/半价抽卡/免费抽卡三种（当前 25min 任务配星星）。
