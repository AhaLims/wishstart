## 1. 系统架构

### 1.1 整体架构

```
┌─────────────────────────────────────────────────────────────┐
│                     Docker Compose                          │
│  ┌─────────────────┐          ┌─────────────────┐           │
│  │   Frontend      │          │     Backend     │           │
│  │   (Nginx)      │◄────────►│    (Node.js)    │           │
│  │   :80           │  HTTP   │    :3000        │           │
│  └─────────────────┐          └────────┬────────┘           │
│                                         │                    │
│                                  ┌──────▼──────┐            │
│                                  │    Redis     │            │
│                                  │   :6379      │            │
│                                  └─────────────┘            │
└─────────────────────────────────────────────────────────────┘
```

### 1.2 技术栈

| 层级 | 技术选型 | 说明 |
|------|----------|------|
| 前端 | Vue 3 + Vite | 现代化前端框架，快速开发 |
| 后端 | Node.js + Express | 轻量级后端服务 |
| 数据库 | Redis | 键值存储，适合游戏化数据 |
| 部署 | Docker Compose | 容器化部署 |
| Web服务器 | Nginx | 静态资源服务 |

## 2. 数据结构设计（Redis）

### 2.1 键命名规范

- 所有键使用冒号分隔：`prefix:entity:id:field`
- 前缀统一为 `wishstar`

### 2.2 数据表结构

#### 2.2.1 用户信息 (Hash)

**Key**: `wishstar:user:{userId}`

| 字段 | 类型 | 说明 |
|------|------|------|
| id | String | 用户ID |
| name | String | 用户名称 |
| total_stars | Integer | 累计获得星星总数 |
| current_stars | Integer | 当前剩余星星数量 |
| draw_count | Integer | 全价抽卡次数 |
| half_draw_count | Integer | 半价抽卡次数/掷骰子次数 |
| created_at | Integer | 创建时间戳 |
| updated_at | Integer | 更新时间戳 |

#### 2.2.2 任务列表 (Hash)

**Key**: `wishstar:tasks:{taskId}`

| 字段 | 类型 | 说明 |
|------|------|------|
| id | String | 任务ID |
| user_id | String | 所属用户ID |
| name | String | 任务名称 |
| stars_per_complete | Integer | 每次完成获得的星星数 |
| max_complete | Integer | 最大完成次数（0表示不限制） |
| current_complete | Integer | 当前已完成次数 |
| reward_stars | Integer | 是否奖励星星（1=是，0=否） |
| reward_half_draw | Integer | 是否奖励半价抽卡（1=是，0=否） |
| reward_draw | Integer | 是否奖励抽卡次数（1=是，0=否） |
| created_at | Integer | 创建时间戳 |
| status | String | 状态（active/finished） |

#### 2.2.3 每日记录 (Sorted Set)

**Key**: `wishstar:records:{userId}:{date}`

| 分数 | 成员 | 说明 |
|------|------|------|
| timestamp | JSON字符串 | 记录详情 |

**记录JSON结构**:
```json
{
  "id": "record_id",
  "task_id": "task_id",
  "task_name": "任务名称",
  "stars": 5,
  "type": "task/quick/single",
  "period": "morning/afternoon/evening",
  "is_weekend_double": false,
  "created_at": 1234567890
}
```

#### 2.2.4 愿望列表 (Hash)

**Key**: `wishstar:wishes:{wishId}`

| 字段 | 类型 | 说明 |
|------|------|------|
| id | String | 愿望ID |
| user_id | String | 所属用户ID |
| name | String | 愿望名称 |
| icon | String | 愿望图标 |
| total_fragments | Integer | 合成所需碎片总数 |
| current_fragments | Integer | 当前已收集碎片数 |
| status | String | 状态：collecting（收集中，未集满）/ ready（已集满，待合成）/ completed（已完成） |
| created_at | Integer | 创建时间戳 |
| completed_at | Integer | 完成时间戳 |

**愿望状态说明**:

| 状态 | 含义 | 能否被抽中碎片 | 页面区域 |
|------|------|----------------|----------|
| collecting | 正在收集中，且未收集完成 | ✅ 可以 | "收集中" |
| ready | 已集满，等待用户手动合成 | ❌ 不可以 | 仍在"收集中"，显示"已集满，可以合成" |
| completed | 已由用户手动点击"合成"完成 | ❌ 不可以 | "已完成" |

> `completed_at` 仅在用户手动合成（状态变为 completed）时写入；抽卡集满进入 ready 状态时不写入。

#### 2.2.5 抽卡记录 (List)

**Key**: `wishstar:draws:{userId}`

按时间顺序存储抽卡记录，最新记录在前。

#### 2.2.6 流水记录 (Sorted Set)

**Key**: `wishstar:logs:{userId}`

| 分数 | 成员 | 说明 |
|------|------|------|
| timestamp | JSON字符串 | 流水详情 |

**流水JSON结构**:
```json
{
  "id": "log_id",
  "type": "income/expenditure",
  "category": "task/draw/dice",
  "amount": 5,
  "description": "完成任务获得星星",
  "created_at": 1234567890
}
```

#### 2.2.7 骰子使用记录 (Hash)

**Key**: `wishstar:dice:{userId}:{date}`

| 字段 | 类型 | 说明 |
|------|------|------|
| dice_result | Integer | 骰子点数（1-6） |
| stars_earned | Integer | 获得的星星数 |

#### 2.2.8 索引集合

- 任务索引: `wishstar:tasks:index:{userId}` → Set(taskId)
- 愿望索引: `wishstar:wishes:index:{userId}` → Set(wishId)

## 3. API 设计

### 3.1 接口规范

- 基础URL: `/api/v1`
- 请求格式: JSON
- 响应格式: JSON
- 认证方式: 简单用户ID（可通过URL参数或Header传递）

### 3.2 用户接口


```json
  }
```

### 3.7 抽卡接口

#### 3.7.1 抽卡

```
POST /api/v1/draws
```

**请求体**:
```json
{
  "userId": "user_001",
  "type": "stars",
  "drawType": "normal"
}
```

**说明**:
- `type`: stars（消耗星星）
- `drawType`: normal（全价5颗）或 half（半价3颗+1次半价次数）

**响应**:
```json
{
  "code": 0,
  "data": {
    "wishId": "wish_001",
    "wishName": "想要的礼物",
    "fragmentIndex": 3,
    "currentFragments": 4,
    "totalFragments": 10,
    "isReady": false
  }
}
```

**说明**:
- 抽卡只会抽中「收集中且未集满」（status = `collecting` 且碎片未满）的愿望
- 碎片集满后，愿望状态变为 `ready`（已集满，待合成），继续显示在"收集中"区域
- `isReady` 为 true 表示本次抽卡后该愿望已集满，等待用户手动合成

---

### 3.8 愿望合成接口

#### 3.8.1 合成愿望

```
POST /api/v1/wishes/:wishId/complete
```

**前置条件**:
- 愿望碎片已集满（status 为 `ready`，或 status 为 `collecting` 但碎片已满）
- 愿望尚未完成（status 不为 `completed`）

**响应**:
```json
{
  "code": 0,
  "data": {
    "wishName": "想要的礼物",
    "completedAt": 1234567890
  }
}
```

**说明**:
- 只有用户手动点击"合成愿望"，愿望状态才会从 `ready` 变为 `completed`
- 合成成功后，愿望移动到"已完成愿望"区域

## 5. Docker Compose 部署

### 5.1 目录结构

```
wishstart/
├── docker-compose.yml
├── backend/
│   ├── Dockerfile
│   ├── package.json
│   └── src/
│       ├── index.js
│       ├── routes/
│       ├── services/
│       └── utils/
├── frontend/
│   ├── Dockerfile
│   ├── nginx.conf
│   ├── package.json
│   └── src/
└── redis/
    └── redis.conf
```

### 5.2 docker-compose.yml

```yaml
version: '3.8'

services:
  redis:
    image: redis:7-alpine
    container_name: wishstar-redis
    ports:
      - "6379:6379"
    volumes:
      - redis-data:/data
      - ./redis/redis.conf:/usr/local/etc/redis/redis.conf
    command: redis-server /usr/local/etc/redis/redis.conf
    networks:
      - wishstar-network

  backend:
    build: ./backend
    container_name: wishstar-backend
    ports:
      - "3000:3000"
    environment:
      - NODE_ENV=production
      - REDIS_HOST=redis
      - REDIS_PORT=6379
    depends_on:
      - redis
    networks:
      - wishstar-network

  frontend:
    build: ./frontend
    container_name: wishstar-frontend
    ports:
      - "80:80"
    depends_on:
      - backend
    networks:
      - wishstar-network

networks:
  wishstar-network:
    driver: bridge

volumes:
  redis-data:
```

### 5.3 后端 Dockerfile

```dockerfile
FROM node:18-alpine

WORKDIR /app

COPY package*.json ./
RUN npm install --production

COPY . .

EXPOSE 3000

CMD ["node", "src/index.js"]
```

### 5.4 前端 Dockerfile

```dockerfile
FROM node:18-alpine AS builder

WORKDIR /app

COPY package*.json ./
RUN npm install

COPY . .
RUN npm run build

FROM nginx:alpine

COPY --from=builder /app/dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf

EXPOSE 80

CMD ["nginx", "-g", "daemon off;"]
```

### 5.5 前端 Nginx 配置

```nginx
server {
    listen 80;
    server_name localhost;
    root /usr/share/nginx/html;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://backend:3000/api/;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_cache_bypass $http_upgrade;
    }
}
```

### 5.6 Redis 配置

```redis
bind 0.0.0.0
protected-mode no
appendonly yes
```

## 6. 部署步骤

### 6.1 依赖镜像（部署前置条件）

部署前需要准备以下镜像（`docker compose up` 时会自动拉取，也可以在部署前手动拉取）：

| 镜像 | 用途 | 来源 |
|------|------|------|
| `redis:alpine` | Redis 数据服务 | Docker Hub |
| `node:18-alpine` | 后端运行时基础镜像；前端构建阶段基础镜像 | Docker Hub |
| `nginx:alpine` | 前端运行阶段基础镜像（托管静态文件） | Docker Hub |

```bash
# 手动拉取依赖镜像（可选，跳过则 compose 启动时自动拉取）
docker pull redis:alpine
docker pull node:18-alpine
docker pull nginx:alpine

# 确认镜像已就绪
docker images redis:alpine node:18-alpine nginx:alpine
```

> 注意：若网络无法访问 Docker Hub，需要先通过可用的镜像源拉取，或将镜像导出/导入（`docker save` / `docker load`）到本机后，再执行部署步骤。

### 6.2 启动服务

```bash
# 进入项目目录
cd wishstart

# 启动所有服务
docker-compose up -d
```

## 8. 核心业务规则

### 8.1 星星规则

- 完成任务/快速记录可获得星星
- 周末（周六、周日）获得的星星翻倍
- 星星用于抽卡（全价5颗/半价3颗+1次半价次数）

### 8.2 掷骰子规则

- 每获得5颗星星，获得1次掷骰子机会（无上限）
- 掷骰子消耗1次机会
- 掷出几点就获得几点星星

### 8.3 愿望合成规则

愿望共有三种状态：

1. `collecting`（收集中）：正在收集中且未集满的愿望，抽卡时可被抽中碎片
2. `ready`（已集满，待合成）：碎片已集满，但仍显示在"收集中"区域，抽卡时不会被抽中；用户手动点击"合成愿望"后才进入已完成
3. `completed`（已完成）：用户手动合成后，愿望移动到"已完成愿望"区域

- 抽卡可获得愿望碎片（仅 `collecting` 且未集满的愿望会被抽中）
- 碎片集满后，愿望状态自动变为 `ready`，继续显示在"收集中"区域，并展示"已集满，可以合成"
- 只有用户手动点击"合成愿望"按钮，愿望才会变为 `completed` 并移动到"已完成愿望"区域
- 已完成愿望仍显示完整卡片，方便查看历史
