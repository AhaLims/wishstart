## 1. 先记住：加一本收集册，代码一个字不用动

讨论宝石时反复确认过的一件事 —— **素材是唯一的成本，代码不是**：

| 事实 | 在哪 |
| --- | --- |
| 加一本 = 加一个数据文件 + 在登记处 `require` 一行 | `backend/src/data/collections/index.js` |
| 后端按 `bookId` 泛化，没有一处假设「只有一本」 | `routes/collections.js` 的 `listBooks().map(...)`、`POST /:bookId/buy` |
| 前端一个写死的「火锅」「肥牛」「18」都没有 | `views/Starlight.vue`（只有一句注释在提醒别写死） |
| 一本的外形全在数据文件里：本名、格子、档、价格、容器名、动作名、集齐文案 | `backend/src/data/collections/hotpot.js` |

所以「宝石要不要做」这个问题，**只等于**「宝石的图从哪来」。这也是 8.9 那句话的意思：
「主题之间的差别不在玩法，在美术……这是唯一随主题数线性增长的成本」。

**唯一的例外**：如果宝石要做成「一种多粒」（祖母绿 ×3、能攒数量），那已经买的格子存的是
**set**（成员形如 `hotpot:mushroom`，有/没有两态），**表达不了数量**，得换成 hash 记计数
—— 那就不是加数据文件了。**这个问题要在动手之前先定死。**

## 2. 三条路线

| | 授权 | 成本 | 风格风险 | 什么时候选 |
| --- | --- | --- | --- | --- |
| **A. 继续用 emoji** | 系统自带 | **0** | 无（已经在用） | 现在。能用就不换 |
| **B. 换一套开放授权的 emoji / 图标集** | CC0 或 OFL | **低** | 低：还是平滑风格，跟现在的外壳搭得住 | **首选**。解掉「系统 emoji 里宝石只有 💎💠🔮 三个」这个天花板 |
| **C. 像素风** | 大多是 CC0，生态最肥 | 中（含连带 CSS 改动） | **高**：像素是很强的风格，会跟平滑外壳 + 彩绘立绘互相顶 | 想清楚了再走，见第 5 节 |

**先说一条不要走的路：从商业游戏（比如《洛克王国》）里扒素材。** 两个理由，都不是
道德说教，是实际成本：

1. **版权**：那是别人的美术资源，而这是个提交进 git 仓库的项目，一提交就等于在分发
2. **技术上更贵**：那类图是位图、带背景、尺寸不齐，要塞进 48px 的深色格子里得一张张抠
   背景 —— **比直接找现成的图还费事**

## 3. 素材库清单

### 3.1 开放授权的 emoji / 图标集（路线 B）

卡住当前的从来不是「没有宝石素材」，是**操作系统的 emoji 表就那么大**。换成开放授权的
集子，天花板立刻没了，而且仍然是「不画图」。

| 集 | 授权 | 要署名吗 | 特点 |
| --- | --- | --- | --- |
| **Noto Emoji**（Google） | OFL 1.1 / Apache 2.0 | **不用** | 最宽松，最省心 |
| **Twemoji**（Twitter/X） | 图形 **CC BY 4.0**，代码 Apache 2.0 | **要** | 扁平干净，最贴合现在这种界面 |
| **OpenMoji** | **CC BY-SA 4.0** | 要，**且 share-alike** | ⚠️ 见下面的注意 |

⚠️ **OpenMoji 的 share-alike 会粘在素材上**：给宝石换个填充色算**衍生作品**，那份改过的
SVG 得跟着 CC BY-SA 开源。**不是**传染整个前端，但**那份素材是**。

**矢量图标库（另一条路，但风格不同）**：

| 来源 | 授权 | 有什么 | 注意 |
| --- | --- | --- | --- |
| **game-icons.net** | **CC BY 3.0** | 4000+ 个 SVG 图标，有 food 分类，搜 gem / crystal / diamond 能找到宝石 | 署名即可；但**是单色线条风**，跟现在的彩色 emoji 不是一路 |

### 3.2 像素风（路线 C）

**像素风是免费素材生态最肥的一档** —— 比 emoji、比矢量图标都多。

| 来源 | 授权 | 有什么 |
| --- | --- | --- |
| **Kenney**（kenney.nl） | **CC0**（不用署名、可商用） | **Tiny 系列**（Tiny Town / Farm / Dungeon，16×16）、Roguelike / RPG 包、**Pixel UI Pack**（750+ 按钮面板，带九宫格） |
| **0x72 DungeonTileset II**（itch.io） | **CC0** | 16×16，公认最好用的免费像素图集之一，**里面就有道具和武器** |
| **itch.io** | ⚠️ **逐个不同，必须看 LICENSE** | Sprites 标签下 6800+ 包。筛 `Tag: Pixel Art` + `License: CC0` + `Free`。可靠的 CC0 作者：**Pixel Frog**、**Ansimuz**、**Pixel Boy** |
| **OpenGameArt** | 混杂 | 高级搜索里**有 CC0 勾选框**，能直接筛掉要署名的 |

### 3.3 通用素材（不限定风格）

| 来源 | 授权 | 有什么 |
| --- | --- | --- |
| **Kenney** | **CC0** | 100+ 包、几万件，有 Food Kit；2D 那边有 Items 一类收集品图集 |
| **OpenGameArt / itch.io** | 混杂 | 同上，量大但要挑 |

**授权速记**：`CC0` = 公共领域，**最省事**（不用署名、可商用）；`CC BY` = 署名即可；
`CC BY-SA` = 署名 **+ 衍生作品也得同授权**（会粘在素材上）；`CC BY-NC` = **不能商用**。

⚠️ **表里的授权是 2026-09-23 查到的，下载那一刻再打开包里的 LICENSE / README 看一眼** ——
授权是会改的（itch.io 上尤其，同一个作者不同包都可能不一样），而「以为能商用结果不能」
是事后很难补救的那类错。**要署名的话，署名写在哪儿也要一起定**（比如页脚或一个
`ASSET_LICENSES.md`），别等到要发的时候才想起来。

## 4. 两个「不用找图」的做法

这两条比去素材库下载更值得先试，因为它们**不引入新风格**。

### 4.1 换 emoji 集 ≠ 换图（路线 B 的本质）

不是去找「宝石素材」，是把 emoji 的**渲染来源**从「系统字体」换成「自己的 SVG 集」。
前端只是个取图方式的变化，**数据结构不用动**（数据文件里那个 `emoji` 字段还是写 emoji
字符，只是取图时不再交给系统字体）。做完这一次性改动，之后每加一本还是只写数据文件。

### 4.2 一个形状 × N 个颜色

开放的 emoji 集是**扁平 SVG、纯色块** —— **一个 💎 的形状换个填充色，就是红宝石、祖母绿、
紫宝石、钻石**。一套宝石 = 1 个形状 × N 个色值，不是一个宝石一张图。

像素风里这更是**原生操作**（调色板替换）：

- **[LibreSprite](https://libresprite.github.io/)** —— 免费开源（Aseprite 的分支）
- **Piskel** —— 网页版，免费，不用装
- Aseprite 本体是付费的，不是必需
- **Lospec** 的免费调色板库：**同一套 palette 出来的图看着才像一家的**，这是让 N 个宝石
  不散架的关键

这一条正好把 8.9 那句「素材不能复用……唯一随主题数线性增长的成本」拆掉一半 —— 至少到
「同一大类的不同颜色 / 不同小件」这个层次，成本从 **N 张图**降到 **1 张图 + N 个色值**。

## 5. 真要换素材时必须知道的坑

### 5.1 像素风的两个坑（路线 C，必看）

**① `image-rendering: pixelated` 一定要加。**

```css
.dish-emoji { image-rendering: pixelated; }
```

不加的话浏览器会做双线性平滑，像素画直接糊成一团 —— **这是最常见的翻车点**。

**② 尺寸必须整数倍。**

现在格子里是 `font-size: 1.8rem` ≈ **28.8px**（`views/Starlight.vue` 的 `.dish-emoji`）。
16×16 的图放进去是 **1.8 倍**，像素大小不匀（有的占 1px、有的占 2px，看着毛毛的）。

换像素素材就得把槽位调成 **32px（2×）或 48px（3×）**。**这是连带改动，不是纯替换。**

### 5.2 好消息：黑剪影不用重做

没买的格子现在靠这个压黑（8.5 定的「不另做一套剪影图」）：

```css
.dish-emoji { filter: brightness(0) opacity(0.38); }
.dish-owned .dish-emoji { filter: none; }
```

**这个滤镜对任何带透明通道的图都成立** —— emoji 换成 PNG / SVG 照样压成黑的。
8.5 省下来的那套剪影图，换成任何素材都一样省。

### 5.3 深色底要单独看一眼

锅底是深色的（格子是 `rgba(0,0,0,0.14)`）。像素素材通常按**自己的调色板**画的，直接放到
深色底上可能**糊在背景里**，需要一圈浅色描边。emoji 和矢量图标自带浅色轮廓，所以现在
没这个问题。

### 5.4 风格上要说清楚的实话

这页**现在已经是混搭**：精灵是 wiki 的**彩绘立绘**、食材是**系统 emoji**。加像素等于
**再加第三种风格**。

而且：**emoji 是「中性」的，像素不是。** 现在这套外壳（圆角卡片、渐变、发光）是平滑风格，
emoji 也是平滑的，所以搭得住；像素是**很强的风格**，它会跟平滑外壳和彩绘立绘互相顶。

有些游戏就这么干（立绘细致 + 道具图标像素），成立 —— 但那是个**有意拍板的选择**。
真想协调，按 8.9 自己的逻辑，得让**整块收集区**（锅 + 格子 + 道具）一起变像素，嵌在现在
这个平滑外壳里当一块「像素小天地」—— 那就不止是换素材了。

## 8. emoji 实测清单（2026-09-24 在这台机器上实跑过）

**不是凭记忆列的。** 做法：headless Chrome 里把每个字符画进 canvas，跟「一个保证没有
字形的私用区码点」画出来的 notdef 方块逐像素比 —— 一样就是**没字形**（页面上会是一个
豆腐块）。检查脚本先跑 🥬🍗💎 三个已知一定有的当对照组，对照组正常才认这份结果。

一共测了 ~200 个候选，覆盖面：火锅的汤底/调料/配菜、超市的 6 个货架。

### 8.0 两条通用规则（挑 emoji 前先记住）

**① 这台机器的 emoji 字体停在 Unicode 13（2020）。**

实测**没字形的一共 6 个，全都是 Unicode 14（2021）新增的**：

| 字符 | 想要的语义 | | 字符 | 想要的语义 |
| --- | --- | --- | --- | --- |
| 🫗 | 倒油 / 倒液体 | | 🫙 | 罐子（酱油？） |
| 🫚 | 姜 | | 🫘 | 豆子 |
| 🫧 | 泡泡 / 洗衣液 | | 🪮 | 梳子 |

**所以：挑 emoji 时避开 Unicode 14（2021）以后的，就不会踩坑。** 上面 6 个看着都很
合用，但**现在这台机器上它们全是豆腐块**。

**② ZWJ 组合序列别用。** 比如 🍄🟫（褐蘑菇）、🍋🟩（青柠）—— 字体缺这个组合时**不会变成
豆腐块**，而是**悄悄渲染成前后两个 emoji**（🍄 和 🟫 并排）。上面那个检查**查不出来**
这一类，只能靠记：**只挑单个码点的 emoji。**

### 8.1 火锅卡池还能加什么

先把三样东西分开 —— 它们的结论**完全相反**：

#### (a) 汤底 / 锅底 → 别当格子，当**前置链**

`核心功能` 8.9 已经把它想成另一个机制了：「**前置链**：买了锅底才能买肉、有了房子才能
买车位。纯一张依赖表，把「一次买齐」变成「一步步来」。」

这比多加一格值钱得多 —— **它给了「一次买齐」一个顺序**，而现在 39 样是随便买的
（加出五档之后**价有高低、但顺序还是随便**：档只管单价，不管先后 —— `hotpot.js` 里 `itemsOf()`
是按「档的声明顺序 + 档内顺序」重排的，而页面**根本不显示档位名**，所以档在观感上是不存在的）。
emoji 上 🫕（芝士火锅）或 🍲 都能用，但它是个**门槛**，不是一格菜。

#### (b) 调料（油 / 盐 / 酱油 / 醋 / 糖）→ ⚠️ **emoji 基本没有**

**这是结论最硬的一条。** 实测能用的只有：

| 有 | 🧂 盐 · 🌶️ 辣椒 · 🧄 蒜 · 🧅 洋葱 · 🌿 香草 |
| --- | --- |
| **没有** | **油、酱油、醋、白糖、味精、花椒、豆瓣酱、蚝油、料酒 —— 一个 emoji 都没有** |

不是没想到，是 **Unicode 里根本没有这类字符**。硬凑只能用「代指」，但都不成立：

- 🛢️ 油桶 —— 是工业油桶，不是食用油
- 🧴 瓶子 —— 是个没标签的塑料瓶，看不出是什么
- 🪨 岩石（当花椒）—— **而且是黑白的**，放进锅里像是坏了
- 💨 蒸汽 / 🪨 —— 同上，黑白

**所以：如果调料这一档要做，就得走第 2 节那条路（矢量图标或像素素材），emoji 撑不住。**
这恰好是本文档开头那句「卡住你的不是没有素材，是系统 emoji 表就这么大」的第一个具体例子。

**而且实测截图又补了一刀**：🧂 盐在这台机器上渲染出来是一个**深灰近黑的盐罐**，
放在深棕色的锅底上**几乎看不见**（🛢️ 油桶同理，是个黑油桶）。所以这一档不但「没几个
能用的」，**能用的那个还正好是看不见的**。

#### (c) 配菜 / 生鲜 → ✅ 空间很大，30 多个现成的

实测**全部有字形、且是彩色**。标了 **(已用)** 的是 2026-09-24 加进火锅的那批（锅从 18 格
加到 39 格），**没标的还能用**：

**「档位怎么加」现在真加过一次了**：从两档（素 8000 / 荤 14000）加到五档 —— **档 = 价，纯数据**，
加档就是往 `hotpot.js` 的 `tiers` 里加一行（**漏了这行服务直接起不来**，启动有自检兜着）。
那次加出来的台阶是：饮料 6000 < 素菜 8000 < 主食 10000 < 荤菜 14000 < 招牌 30000，
总数 204000 → 456000。

要记住的还是 8.3 那句的连带影响：**样数越多解锁越密**，而总价是按「一锅 ≈ 两周」反推的 ——
**加样数要跟着调价**。那次就是照这条做的：新加的档一个都不便宜（只有饮料比素菜低一档），
所以每样的均价基本没变（11300 → 11700）。

**两个要注意的（不是 emoji 的问题，是设计的问题）**：

1. **8.5 那条「锅一直在冒泡」的体感要求要另找落点。** 那条明确写了「这条比下面那下解锁
   动画更影响体感，别做成一张静止的图」。超市换成 🛒 之后**没有会冒泡的东西了**，得另
   找一个「一直在动」的元素（传送带？收银台指示灯？日光灯闪？）—— **这是超市这本唯一
   真正的新设计工作量**。
2. **`🧊` 被我拿去当「豆腐」和「魔方」用了两次** —— 一个 emoji 在同一本里只能占一格，
   跨本也别重复，不然两本看着像同一套。

### 8.3 深色底上「发黑」的几个（只有真看一眼才发现）

**有字形 ≠ 放进锅里看得清。** 所以把候选按**锅里的真实样式**（同一个 `1.8rem`、同一块
`rgba(0,0,0,.14)` 的深色格子、同一个「没买 = `brightness(0)` 压黑」滤镜）排出来截了一张
图看过 —— 这一眼查出了逐像素检查查不出来的东西：**有几个 emoji 本身就是深色的，
在深棕色的锅底上对比度太低，看着像没渲染出来**。

| 发黑的 | 说明 |
| --- | --- |
| 🧂 盐 | **深灰近黑的盐罐** —— 这是「调料档」里唯一能用的一个，却正好看不见 |
| 🛢️ 油桶 | 黑油桶，同上 |
| 🛋️ 沙发 | 深色沙发 |
| 🏷️ 标签 | 深色标签 |
| 🥥 椰子 | 深棕色，跟锅底撞色 |
| 🫓 饼 | 灰白，边缘糊在背景里 |

**判据：挑完 emoji 一定要按真实样式排一遍看一眼**，别只看「有没有字形」。这条**真的筛掉过一个**：
🫓 饼本来要给火锅的主食当第 4 格，看出来发黑之后换成了 🍙 饭团 —— 而它最难看的时候恰好是
**买下来、从灰剪影变成彩色那一刻**，也就是奖励的那一下。
这个检查脚本（`ws-emoji-check.cjs`）和截图脚本（`ws-emoji-shot.cjs`）都在
`%TEMP%` 下，要复用时把候选列表换成新的就行。

**顺带确认了一件事**：`brightness(0)` 压出来的黑剪影**在深色底上是看得清的**
（西兰花、卷纸那两个剪影一眼能认出形状），8.5「不另做一套剪影图」这条**对所有 emoji
都成立**，不用挑。
